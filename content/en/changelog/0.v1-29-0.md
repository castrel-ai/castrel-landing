## New Feature: Health Checks Link Incidents and Alerts

When an application health check comes back critical, Castrel uses the current evidence and past check history to look for an open incident in that application with matching symptoms. If one exists, Castrel reuses it and only adds new, verifiable findings, so the same risk doesn't produce duplicate incidents.

If there's no matching incident, Castrel creates one and sets its severity based on impact. Before creating it, Castrel queries the application's related alerts, not just the ones currently firing, filters them by symptom, time, status, and severity, and links them to the new incident. Investigators open the incident and find the check evidence and alert context already there.

The health check report records which incident was reused or created, its latest status, investigation progress, and linked alerts. If the alert query fails or is limited, the report says why. Each report is saved as application knowledge for future checks to reference.

## Full Release Checklist

### feat

- Added automatic incident linking for critical health check results: Castrel reuses a matching open incident or creates a new one, and links related alerts.
- Added bulk download on the knowledge page.
- Added model, thinking mode, and reasoning effort selection to automations (defaults to Auto); sessions triggered by an automation show the selected model.
- Added an optional goal condition to automations, so tasks keep running until the goal is met; it can also be set when creating or editing an automation in chat.
- Improved manual runs so they no longer require the automation to be enabled; the enabled state now only controls scheduled and event triggers.
- Added automatic task linking for events, and sessions now show their associated automation.
- Removed the / command menu from the automation instructions editor.
- Restructured the underlying implementation of sign-in, sign-up, workspace management, settings, and sessions for better stability.

### bugfix

- Fixed an issue where IM plugin connections such as Lark, DingTalk, WeCom, Telegram, WPS, and Email could not be selected when binding knowledge to a plugin.
- Fixed the permission badge in automation instructions defaulting to "Ask for approval", which did not match actual behavior; it now always shows "Full access".
