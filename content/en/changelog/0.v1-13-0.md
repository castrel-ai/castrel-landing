## New Feature: Chat Experience Overhaul

This release delivers the most wide-ranging redesign of the Chat page to date, spanning five dimensions: the message reading area, task process display, input box, Canvas Tab, and the sidebar.

**Message reading area and interactions:** The left reading column is now narrower, increasing information density in long conversations. Agent final output no longer uses incorrect blockquote indentation. User messages display an avatar on the right. Hovering over any User or Agent message reveals a timestamp and a copy action below the message — copying captures only the body text, excluding tool call inputs and outputs.

**Task process folding** is the most visible change in this release. Agent execution steps are now collapsed by default. The summary row shows the step count and elapsed time (e.g., "Worked for {duration}"), with a lightweight expand/collapse animation. Tasks that are in progress or were interrupted cannot be collapsed, keeping error and active states always visible.

**Tool call display** has been reworked to a lighter ghost style. Clicking a tool call opens it in the right Canvas for details rather than expanding inline. Repeated calls to the same toolset are merged into a single entry (e.g., "Used Prometheus × 3"). Todo tool calls are hidden from the process area to reduce noise.

**Canvas Tab:** Entering a historical session now auto-focuses the last artifact of the most recent conversation round. Closable tabs use a hover-to-reveal × icon on the left instead of a dedicated close button. Document and knowledge tabs display the actual document name rather than a generic type label.

**Sidebar task list:** Regular conversation rows no longer reserve space for an icon — their titles align with group heading text. Sub-agent conversations are indented one extra icon-width to visually express the parent–child task relationship.

## New Feature: AI Question Interaction Redesign

When an Agent needed to ask the user a question, the previous experience popped open a Canvas card on the right, breaking the conversation flow, while the input box still showed "AI is generating a response" — a misleading status message.

The `ask_user_question` interaction has been moved into the input box area as an **interrupt-style question panel**. While waiting for a user response, the input box switches to a lightweight question panel so users can answer within the current conversation context without switching to a side card. The panel supports recommended options, regular options, and free-text input. When there are multiple questions, a header shows the current position (e.g., 1/3) with left/right navigation. ESC dismisses the panel. The right Canvas no longer opens automatically — it only opens when the user explicitly clicks a tool call to view its details.

This interrupt mechanism is built as a generic input interrupt slot inside the input box component, making it reusable for other tools that require user input in the future.

## RCA Studio Capability Upgrade

This release brings systematic upgrades to the RCA fault analysis workspace across four areas.

**Fault propagation topology upgrade:** The global Application topology is now overlaid on the existing fault path view, using three visual layers to immediately convey the full scope of an incident — fault propagation nodes in red, affected objects in yellow, and normal nodes in the default style. Investigators can see the fault core and its blast radius at a glance without switching between multiple views.

**Incident Pattern MVP:** RCA now supports extracting, matching, storing, and reusing fault patterns from historical incidents. When a known Pattern is matched, its inference chain is reused directly to accelerate root cause analysis. When no historical precedent exists, mechanism-based matching (e.g., resource exhaustion, cascading failure, config drift) narrows the hypothesis space. When neither matches, the original RCA reasoning flow is used as a fallback.

**Fault context management redesign:** All RCA nodes now share a unified App-aware context, containing raw metadata, App information, upstream signals, and the hypotheses, conclusions, and evidence accumulated during the investigation. This ensures full context propagation throughout the entire investigation, making conclusions coherent and traceable.

**RCA Agent plugin integration:** The RCA Agent has been refactored as a plugin and integrated with the Copilot on the RCA home page. Users can now use Copilot to query historical incidents, run statistical analysis, identify trends, generate comprehensive summaries, and produce periodic reports — transforming RCA from a single-incident tool into a sustained fault analysis platform.
