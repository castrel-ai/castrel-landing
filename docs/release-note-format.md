# 发版文档格式规范（Release Note Format）

本规范用于 `content/{zh,en}/changelog` 下发版文档。自 `v1.4.0` 起，新版本统一采用本格式。

## 1. 术语规范

- 中文文案中，Automation 统一写作「自动化」。
- 产品文案中，Bridge / BridgeNode 统一写作「Castrel Proxy」。
  - `Bridge*` 仅在代码语境出现，不作为对外发版名词。

## 2. 标题与字段规范

- `title` 不写版本号（版本号只放在 frontmatter 的 `version` 字段）。
- 禁止使用“第一部分/第二部分/第三部分”这类章节标题。

## 3. 固定章节结构（四章）

每篇发版文档固定为以下四个章节：

1. `新功能：自动化`
2. `Proxy 新增代理模式`
3. `新增 x 项集成（并标注增强项）`
4. `完整发版清单`

## 4. 各章节写法要求

### 新功能：自动化
- 用 1~2 段简短文字说明功能价值与变化。
- 不用仅罗列点。
- 需要放对应文档链接（站内 docs）。

### Proxy 新增代理模式
- 用 1~2 段简短文字说明功能价值与变化。
- 不用仅罗列点。
- 需要放对应文档链接（站内 docs）。

### 新增 x 项集成（并标注增强项）
- 集成项必须显式区分：`新增` 或 `增强`。
- 禁止使用“新增/增强：xxx”这种混写。

### 完整发版清单
- 分为 `feat` 与 `bugfix` 两个小节。
- 逐条列出，语句需可验证。

## 5. description 写法

- `description` 用 2~3 句话，概述前两个核心功能章节（自动化、Castrel Proxy）。
- 不写成长摘要。

## 6. i18n 要求

- 中英文 changelog 同步维护。
- 结构一致，语义对齐。

## 7. 模板

```md
---
title: <不含版本号的标题>
description: <2~3 句话，概述自动化 + Castrel Proxy>
version: vX.Y.Z
---

## 新功能：自动化
<1~2 段文字 + 文档链接>

## Proxy 新增代理模式
<1~2 段文字 + 文档链接>

## 新增 x 项集成（并标注增强项）
- 新增：...
- 增强：...

## 完整发版清单
### feat
- ...
### bugfix
- ...
```
